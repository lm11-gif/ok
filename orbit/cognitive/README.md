# ORBIT Cognitive v2

**Status: generator source code committed; CPU CI and a new GPU training run still need to pass before a v2 model release exists.** The previous v1 release remains a retrieval-only prototype. v2 adds a randomly initialised causal Transformer that generates its own text rather than choosing fixed answer templates.

## Architecture

- PerceptionNet identifies likely entities and relations in user questions.
- AssociationNet predicts objects associated with a subject/relation pair.
- MemoryNet retrieves relevant stored facts.
- NeuralLanguageGenerator is a causal Transformer trained to predict the next UTF-8 byte. During inference it generates each answer autoregressively.
- The chat controller provides the user question, recent conversation history, and retrieved facts as context. The final response is sampled by the neural generator, not assembled from fixed answer templates.

All four student networks start from random initialisation. No pretrained weights, embeddings, tokenizer, or hidden states are loaded. The generator uses a byte vocabulary (0–255 UTF-8 bytes, plus EOS=256) so it needs no external tokenizer.

## Training data and limits

The generator trains on the repository's locally authored synthetic multi-turn conversation corpus generated by `orbit/seed_model/make_corpus.py`, plus examples grounded in the 67-fact Cognitive graph. The corpus contains coaching conversations, everyday scenarios, beginner explanations, short stories, roleplay exchanges, and uncertainty examples. Fact-grounded samples include the relevant graph records in a `<|context|>` section.

This is a real next-byte language-modelling objective, not template substitution. However, the model is deliberately small (default 128 hidden dimensions, 4 decoder layers, 4 heads, 384-byte context) and its dataset is synthetic and limited. It is an experimental generator, not a capable general-purpose assistant. Expect weak coherence and factual recall initially; longer training and a much larger, higher-quality corpus will be needed.

The v1 checkpoint does not contain `generator.pt` and cannot run the v2 chat program. Keep the releases separate.

## GPU training

Kaggle supplies PyTorch. The workflow creates a self-contained script and embeds a compressed copy of the authored dialogue corpus so training can run offline. Normal training requires CUDA; CPU is used only for CI smoke tests.

    python -m orbit.cognitive.train --device cuda --output artifacts/orbit-cognitive-v2

Optional generator settings:

    --generator-epochs 12
    --generator-batch-size 32
    --generator-dim 128
    --generator-layers 4
    --generator-heads 4
    --generator-block-size 384

Speed choices include GPU-resident token windows, FP16 autocast and GradScaler on CUDA, fused AdamW when supported, gradient clipping, validation-loss checkpoint selection, and a single Kaggle process. A 384-byte context is shorter in words than a 384-subword-token context.

## CI and release

The CPU CI validates network shapes, generation sampling, the self-contained Kaggle bundle, smoke training, checkpoint loading, chat generation, and archive contents. Only after CI succeeds should the separate Kaggle GPU workflow be triggered. The v2 release will be published as `orbit-cognitive-v2` after the new generator checkpoint is trained and validated.

## Run the v2 model

After the `orbit-cognitive-v2` release exists, download and extract `orbit-cognitive-v2.zip`. From the repository checkout run:

    python -m orbit.cognitive.chat --model path/to/extracted --device cpu

On a machine with CUDA-compatible NVIDIA graphics, use `--device cuda`. An Intel Iris Xe laptop should use CPU.

In chat, enter `/reset` to clear conversation history and `/exit` to quit.

## What this actually changes

A generated answer is sampled from the trained neural network, one byte at a time. That makes v2 genuinely generative, but does not automatically make it coherent or intelligent. The model can hallucinate, repeat itself, or produce malformed text. Retrieved facts are a small evidence context; independent evaluation, larger data, and better evidence verification remain necessary.
